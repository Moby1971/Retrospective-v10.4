# Python packages the Retrospective app needs, for the environment it creates
# itself in venv_retro.
#
# Two tools use python: the DRIM reconstruction, which is torch and lightning,
# and the LV segmentation, which runs its model through onnxruntime. TensorFlow
# is deliberately absent. It used to be needed to read the Keras model, but the
# model is now converted to ONNX, and having both torch and TensorFlow in one
# environment means two CUDA stacks that fight: installing tensorflow[and-cuda]
# pulls an nvidia-nccl version that torch pins against, and pip can only warn.
#
# These pins install on python 3.11 through 3.13, and the app picks an
# interpreter in that range to build the environment on. Below it numpy and
# onnxruntime have no wheel, above it scipy has none, and in both cases pip
# says only that no matching distribution exists. The same range is stated in
# retro.pythonVersionRange, which is what the app actually enforces; change the
# two together.
#
# A machine with no python in that range does not stop here: the app makes one
# with conda, or downloads a self-contained build, or asks homebrew, whichever
# it finds first. The pinned release and its checksums live in
# retro.standalonePythonSources.
#
# Versions are pinned so that every machine resolves the same way and a future
# user gets what was actually tested, rather than whatever pip prefers that
# month. Raise them deliberately, not by accident.
#
# The accelerator packages are left to float: a CUDA wheel has to match the
# host driver, so one pin cannot serve every machine. On Linux and WSL, pip
# picks the CUDA build of torch by itself; on macOS it picks the Metal build.

# torch is deliberately NOT pinned here, and not listed at all.
#
# Which torch wheel is correct depends on the machine: a build carries compiled
# kernels for a set of GPU architectures, and one that does not cover the card in
# front of it installs perfectly and then fails at the first kernel launch with
# "no kernel image is available for execution on the device". A version number
# cannot express that, so pinning one is worse than useless, it is confidently
# wrong on every machine but the one it was written on.
#
# The environment is therefore created with access to the system packages, so a
# torch that already works on this machine, with the CUDA build its driver
# needs, is used as it is. Only when no torch can be imported at all does the app
# install one and let pip choose.

lightning==2.6.5
numpy==2.3.5
scipy==1.15.3
PyYAML==6.0.3

# The segmentation model, as ONNX. onnxruntime-gpu is the CUDA build and is
# installed instead of this one on machines that have a working CUDA driver;
# the app asks onnxruntime for an accelerator and falls back to the CPU by
# itself, so either package works.
onnxruntime==1.28.0
